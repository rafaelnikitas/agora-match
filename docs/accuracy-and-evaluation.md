# Accuracy, evidence and evaluation

## What changed

The three workspaces are preserved. This release corrects football metric definitions, makes analytical evidence follow replay time, reduces the default insight density, and adds inspectable source links and a compact “Why this moment matters” card.

### Correctness fixes

- Penalty-area touches require valid x/y coordinates and the correct attacking direction. A wide corner is excluded. The box dimensions are 16.5m by 40.32m on the 105×68m pitch.
- Successful dribbles include `won` and `complete` outcomes. They are called successful tagged dribbles; progression is unavailable without a validated start/end carry definition.
- A pass receiver gets a touch only when the pass completes. Tied counts share the same rank.
- Sparse speed samples no longer become measured sprint totals or integrated high-speed distance. The app reports high-speed samples and maximum sampled speed. Other same-role players form the peer comparison, excluding the selected player.
- Physical window comparisons appear only once both windows finish. Paired geometry requires both its 55′ and 70′ frames. Neither is presented as a fatigue diagnosis or marking assignment.
- Player pages, chat, and history files share one appearance ledger. Per-shot xG and pass-completion rates expose denominators. Raw tagged current totals and full historical appearances remain explicitly different coverage.
- Completed attack outcomes become available only after their linked sequence finishes. The second fictional match excludes events beyond its stated end.

## One analytical clock

`project_game(source, analysis_time_seconds)` filters the evidence before calculating scores, statistics, ranks, heatmaps, ratings, matchups, insights and recaps. The API validates the cutoff. A future event cannot be retrieved into an earlier answer.

Static hosting serves precomputed analytical states at event, completed-attack and player-snapshot boundaries. These are generated by the same Python projection used by the API. The browser loads only the needed state, suspends sensitive panels while it changes, and stores conversations by match, role, language and analytical context. A rewind does not reuse an answer from a later context. Sharing a link preserves the replay second.

The ball replay can move between evidence boundaries; the banner identifies the latest analytical input time. Interpolated ball positions are illustrative synthetic animation, not observed tracking and not inputs for physical measurements. The actual replay remains browser driven; no licensed external feed is claimed.

Evidence links open the matching event or completed sequence. Passing options and matchup illustrations use a prior player frame, never a later frame. Broadcast exports retain analysis time and an explicit match-time expiry; changing context clears the old preview.

## What the AI can and cannot change

The reader examines a bounded evidence bundle. The writer receives an audience goal and output language and returns:

```json
{"lead":"The recent record adds context to this chance.","fact_ids":["FA","FB"]}
```

The application rejects malformed objects, unknown or duplicate fact IDs, numerical prose, additional fields, and known participants outside the retrieved context. The application inserts selected fact labels and values verbatim. The writer cannot substitute another value into a numerical fact.

In three-role mode, a separate evidence reviewer checks the assembled explanation and can reject it. Failure, timeout or rejection returns the deterministic explanation and its evidence. Unsupported questions skip the model. Cache entries retain the full evidence context and output language; a cache hit is labeled and does not claim a new model execution.

This contract protects the displayed numerical facts. It does **not** mathematically prove every qualitative sentence or causal implication. A model can still misinterpret football context or produce an unhelpful explanation. The reviewer is also a model. Live evaluation and human review are required before asserting semantic accuracy.

English and Greek are supported output-language settings for live AI explanations. Questions and source labels remain English. Without a configured model, Greek requests receive an explicitly marked English fallback. This is not a fully localized interface.

## Reproduce the local evidence

After installing `requirements.txt` into a Python 3.12 environment:

```bash
python -m unittest discover -s tests -q
python scripts/verify_intelligence.py
python -m agora_match.build_site
node tests/browser_evidence.cjs
```

The build regenerates `static/data/verification.json` and refuses a failed synthetic acceptance report. The app's **Checks & limits** drawer reads that report. The checked examples cover independent box boundaries and outcomes, no-future-data cases, changes to future records, incomplete windows, history consistency, unsupported queries, and malformed/swapped fact requests. Browser fallback checks exercise the same time boundaries and question families without a DOM.

Unit/API tests additionally cover provider contracts using mocked HTTP responses, authentication selection, bounded retries, reviewer rejection, numeric injection, rate/concurrency limits, the circuit, and the actual selected-time payload at the API/model boundary. Mocked provider success is an integration test, not a live LLM result.

The existing `scripts/evaluate.py` measures seven known question templates over three roles: 21 routing checks. It measures routing, returned evidence, real-model/fallback rate and latency. Its routing rate is not a semantic accuracy score.

## Run an actual model comparison

Configure Foundry identity and the three role deployment names using the [Azure runbook](azure-readiness.md). No credentials belong in the browser or repository. Then run:

```bash
python scripts/evaluate_models.py --run-live --mode compare \
  --pause-seconds 8 --output build/live-model-evaluation.json
```

This command makes paid model calls. It evaluates a single narrator and the three-role pipeline over the same six supported scenarios, including early-time cases, historical context, coaching output and a Greek explanation. It disables the response cache. The report records actual output, canonical facts, model/fallback status, token usage and latency. A missing configuration produces `status: not_run` and exits unsuccessfully; it cannot manufacture a successful evaluation.

For every returned explanation, manually review the supplied fields for supported qualitative claims, appropriate uncertainty, usefulness for the selected role, and language correctness. Do not convert pending reviews into an accuracy percentage. Compare the two modes on quality, rejection/fallback rate, time and tokens before claiming that extra agents improve the result.

Separately exercise the deployed app:

```bash
python scripts/smoke_azure.py --url https://YOUR-CONTAINER-APP --require-ai
```

The smoke gate requires fresh successful execution of all three roles. It confirms connectivity and execution; it does not certify football reasoning quality. Verify telemetry ingestion and keep both the model comparison report and a browser check as submission evidence.
